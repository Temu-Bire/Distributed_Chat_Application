Everything a good chat needs

Built for the way groups actually talk.

Private conversations

One-to-one chats with anyone in your network. Search users, send a friend request with a note, and open as many direct threads as you need.

Groups with real moderation

Owners and moderators manage members, roles and settings. Public groups are open; private groups run on join requests and invitations. Blocked users are enforced on every entry path.

Replies, reactions, edits

Answer a specific message, react with emoji, edit or delete your own words. Moderators can clear spam — everything updates live for every reader.

Presence and people

See who is online, discover groups by name, and track the state of your friend and join requests without leaving the app.

Reliable by design

Sends are idempotent: if the network hiccups and your client retries, the message lands exactly once. History is saved before it is ever announced.

Yours to run

A single Spring Boot jar with an embedded database — start it locally, or scale the stateless app nodes behind shared Postgres and Redis when your community grows.

Real-time where it matters

ChatSphere keeps an open WebSocket per session and speaks STOMP over it, so joins, messages, edits and reactions stream to every member the moment they happen. Heartbeats detect dead connections, the client reconnects automatically, and each conversation lives on its own subscription — delivered only to members.

  • Bounded thread pools absorb bursts instead of unbounded spawning
  • Transactions commit before any fan-out is published
  • Optional Redis relay propagates events across instances

Security is not an add-on here

The parts you never see, checked by tests you can run.

Passwords, hashed

BCrypt hashes only — the plain password never touches storage, logs, or your session.

Authorization, enforced server-side

Every REST call and every WebSocket subscription is checked against real membership. A message you are not party to is never delivered to you — proved by automated tests.

Sessions, rotated and locked down

Session ids change at login and stop working behind you. Cookies are HttpOnly with SameSite=Lax, and pages ship a strict Content-Security-Policy.

Abuse, budgeted

Login, registration, friend requests and message sends run under per-minute rate limits — brute-force attempts get 429s, not accounts.
